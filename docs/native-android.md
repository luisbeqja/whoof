# whoof on Android (Capacitor) — native BLE + the clean mobile app

The `web/` app is wrapped with [Capacitor](https://capacitorjs.com) so it runs
as a real Android app with native Bluetooth — pairing the WHOOP strap directly
from the phone, no Mac in the loop. It's the **same `web/` codebase**; there is
no second Android codebase.

When opened, the app shows the minimal **Home + Coach** experience
(`web/index.html`): recovery / strain / sleep at a glance, and a chat coach that
knows your full WHOOP history. The detailed dashboard is still one tap away at
`/dashboard.html`.

> Android's WebView (like iOS WKWebView) deliberately omits the Web Bluetooth
> API. `web/js/ble/capacitor-bridge.js` synthesises `navigator.bluetooth` on top
> of the `@capacitor-community/bluetooth-le` native plugin, so the existing BLE
> client code runs unchanged. `js/mobile/app.js` installs the bridge at startup
> when running inside Capacitor.

## One-time setup

Requires **Android Studio** (with an SDK platform installed) and a **JDK 17**.

```bash
npm install                       # pulls @capacitor/android + the BLE plugin
npx cap add android               # generates the android/ project (once)
npm run cap:sync:android          # copies web/ into the native project
npm run cap:open:android          # opens it in Android Studio
```

In Android Studio: pick a device/emulator and press **Run** ▶. That's it — the
strap pairs over BLE the first time you tap **Connect** on the Home screen.

Re-run `npm run cap:sync:android` after any change under `web/`.

## Build a debug APK from the command line

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17     # or any JDK 17
npm run cap:build:android
# → android/app/build/outputs/apk/debug/app-debug.apk
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

## Bluetooth permissions

Declared in `android/app/src/main/AndroidManifest.xml`:

| Permission | Why |
|---|---|
| `BLUETOOTH_SCAN` (`neverForLocation`) | Discover the strap. `neverForLocation` means Android 12+ never asks for location — this app only talks to a known device. |
| `BLUETOOTH_CONNECT` | Connect + read GATT characteristics. |

Legacy declarations for Android ≤ 11 (`BLUETOOTH`, `BLUETOOTH_ADMIN`,
`ACCESS_*_LOCATION`) are merged in from the `@capacitor-community/bluetooth-le`
plugin's own manifest. Capacitor prompts for the runtime permissions on the
first `Connect`.

The bridge calls `BleClient.initialize({ androidNeverForLocation: true })`, the
runtime companion to the manifest flag above.

> **Background / overnight capture** is foreground-only today (the app must be
> open). True background BLE on Android needs a foreground service +
> `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_CONNECTED_DEVICE` — a future
> enhancement, mirroring the iOS `bluetooth-central` background mode in
> [`native-ios.md`](native-ios.md).

## The Coach in the native app

The Coach calls `/api/coach`, a Cloudflare Pages Function backed by **Claude**.
From the Capacitor origin (`localhost`) a relative path won't reach it, so
`js/mobile/app.js` points the Coach fetch at `https://getwhoof.pages.dev` when
running natively. For the Coach to answer, that deployment needs an Anthropic
key set once:

```bash
npx wrangler pages secret put ANTHROPIC_API_KEY --project-name=getwhoof
npm run deploy
```

Without the key the Coach returns a clear "not enabled" message and the rest of
the app (BLE, metrics, Home) works fully offline. See
[`coach.md`](../functions/api/coach.js) source for model/effort knobs
(`claude-opus-4-8`, adaptive thinking, prompt-cached data block).

## Notes

- `android/` is gitignored (regenerated by `npx cap add android`), exactly like
  `ios/`.
- Gradle 8.2.1 / AGP 8.2.1 (Capacitor 6 template). Use JDK 17; newer JDKs need a
  newer Gradle wrapper.
- A signed release build for the Play Store needs a keystore + `assembleRelease`
  — out of scope for personal use.
